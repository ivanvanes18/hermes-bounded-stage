# Порядок работы в Hermes

## Что именно реализовано

Это пользовательский скилл с исполняемыми Python-скриптами, без companion plugin, сервера, нового хранилища памяти или изменения ядра. Сильный родитель передаёт ограниченный этап одному штатному дочернему исполнителю. Дочерний исполнитель не заменяет контроллер: он обслуживает только запросы создания текста. Между такими запросами контроллер самостоятельно выполняет весь доступный последовательный участок.

Нативный исполнитель всё равно делает собственные модельные обращения для чтения пакета, записи ответа и вызова инструмента. Это не полностью безмодельный worker и не переключение модели в рамках каждого tool call.

## Предварительная проверка владельцем

Установочный `doctor` проверяет только локальные признаки и наличие переменной ключа. Он не проверяет фактическую схему native tools, доступность API, model routing или видимость файлов в другом контейнере.

У владельца должны быть доступны terminal, чтение/запись файлов и, для полного режима, `delegate_task`. Используй фактические названия и схемы инструментов сессии. Профиль только с read_file/search_files/session_search/skill_view/skills_list не может исполнять этот скилл. Не расширяй ему права автоматически.

У родителя, native worker и terminal должны совпадать реальные пути к run и скриптам. Особенно проверь это при Docker/Podman и раздельных terminal sessions. Нельзя подменять видимость файла повторным созданием другого run с тем же именем. При несовместимом workspace верни `needs_setup`, не продолжай на другой копии.

## Маршрут модели

Стандартный `delegate_task` использует существующую настройку `delegation.model`; при её отсутствии может наследовать модель родителя. Этот пакет не читает хранилища токенов, не меняет `config.yaml`, не устанавливает новый provider и не задаёт модель несуществующим per-task аргументом.

Установи фактическую идентичность исполнителя по безопасной информации, которую предоставляет текущий Hermes. Не выводи секреты из config/auth/env. Когда модель установить нельзя, сообщи `worker_model: unknown`. Контроллер всегда сообщает `worker_model: not_verified_by_controller`: это честная граница его наблюдаемости, а не признак ошибки обработки файла.

Если дешёвая модель не настроена, владелец может выполнить чисто детерминированный этап без дочернего агента. Генеративный этап на унаследованной дорогой модели требует осознанного выбора владельца; не утверждай, что экономия уже достигнута. Скилл не выполняет такую перенастройку в рамках установки.

## Поручение одному исполнителю

Используй только подтверждённый минимум схемы:

```text
delegate_task(
    goal="Исполни один уже утверждённый ограниченный этап; не перепланируй",
    context="Полностью заполненное содержимое templates/worker-context.md"
)
```

Это иллюстрация tool call, не Python-скрипт для терминала. Подставь реальный run, путь CLI, пути допустимых профильных инструкций, бюджет и известный маршрут. Не передавай всю историю родителя или каталог всех скиллов.

Если runtime вернул handle, а не итог дочернего агента, этап ещё не завершён. Следуй штатному механизму получения результата данной сборки Hermes. Не принимай handle, `status: completed` самой делегации или уверенный текст worker за проверенный артефакт.

Рекурсивная делегация, новые worker-пулы, фоновые серверы и watch-процессы этому скиллу не нужны. Не запускай их.

## Прохождение этапа

Родитель создаёт и проверяет plan/catalog, затем выполняет `init`. Исполнитель начинает с `advance`. Одна команда `advance` может выполнить несколько copy/command действий и все их проверки без участия родителя.

Контроллер возвращает либо конечный результат, либо пакет `awaiting_generation`. В последнем случае worker читает пакет, создаёт только запрошенный текст и вызывает `submit`. Этот вызов проверяет соответствие источников и пакета, однократность nonce, результат и продолжает последующие шаги. Исполнитель не вызывает модель TypeSafe самостоятельно и не выбирает action_id за контроллер.

У Jev есть только меню разрешённых вариантов. Для нескольких действий обязателен вариант `none`; для смысловых проверок используются `supported`, `contradicts`, `insufficient`. Ответы оцениваются по реальным данным, не по отчёту исполнителя «я всё сохранил».

## Что ограничено исполняемо

Карточка допускает не более 8 шагов. Контроллер ограничивает число своих запросов Jev, число своих запросов генерации, время управляемого этапа и каждый запущенный им процесс. После сбоя не повторяет действие автоматически. При генерации срок продолжает идти; просроченную отправку он не принимает.

Контроллер не измеряет все native LLM calls, токены и стоимость дочернего агента. Он также не может остановить произвольные действия worker вне своего интерфейса. Установленные в Hermes лимиты делегации и его sandbox остаются отдельной границей. Не называй число `generations` числом всех API-вызовов.

Успешный отчёт содержит измеренное количество обращений к Jev и возвращённый ею usage. Сбой после отправки запроса может означать оплаченный запрос без полученного usage; поэтому суммы usage могут быть неполными. Данные о сэкономленных деньгах не выводятся из этих счётчиков автоматически.

## Приёмка родителем

Прочитай отчёт, затем вызови `inspect`: проверяются соответствие завершённых шагов плану, хеши источников, артефактов и подключённых команд. Сверь набор исполненных проверок с требованиями профильного скилла. При необходимости выполни отдельный визуальный или содержательный контроль.

`ready_for_parent_review` — все проверки, перечисленные в данной карточке, завершились без блокировки. `final_acceptance: not_performed` остаётся таким всегда: контроллер не присваивает сам себе финальную приёмку.

Если план был неполон, все его проверки могут пройти, но задача останется неправильно решённой. Качество самого плана, достаточность методики, интерпретация норм и итоговая публикация остаются у сильного владельца и пользователя.


## Staged 1.2 addendum: отдельный executor protocol

Описанные выше планы v1/v2 и native delegation сохранены. Новый `route-*` путь имеет отдельные schemas/runtime/state; см. [executor-routing.md](executor-routing.md). Он не меняет global/delegation model и не запускает весь process skill внутри worker. Родитель фиксирует methodology и принимает результат, executor выполняет только один packet. Новая bounded correction не меняет старую v1/v2 retry policy.
