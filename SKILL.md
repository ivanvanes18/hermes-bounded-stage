# Управляемый этап Hermes

Сильная модель — владелец задачи и плана. Python-контроллер — владелец порядка действий и проверок. Jev выбирает из допустимых вариантов и оценивает узкие признаки. Один штатный исполнитель Hermes обслуживает запросы генерации внутри целого этапа. Память, ядро, глобальные настройки и существующие скиллы не изменяются.

## When to Use

Применяй по явному запросу или для повторяемого процесса, который уже можно ограничить 1–8 последовательными шагами с конкретными входами и проверками. Не используй для обычного ответа в чате, открытого исследования или отсутствующей методики. Не создавай новый планировщик поверх всего Hermes.

## Версия 1.2: выбор протокола

Версия **1.2.0 установлена как skill**, но установка сама по себе не активирует реальные executor routes. Новая ветка executor routing вызывается только через `route-*`; см. [новый контракт](references/executor-routing.md) и [adapter protocol](references/adapter-protocol.md). Domain/process bindings задаёт родитель; Shaw остаётся единственным process owner; worker получает только текущий stage. Реальные routes остаются unverified и disabled до отдельных evidence и разрешения.

## Версия 1.3: ограниченный цикл

Версия **1.3.0** добавляет только слой `loop-*`: цепочку ограниченных итераций по stage, которые родитель допустил заранее, с обязательной остановкой у родителя между итерациями и неизменяемым continuation при redirect. Jev не сочиняет stage — она выбирает один пункт закрытого меню или возвращает цикл родителю. Авторитет состояния — create-only ledger переходов, связанный хешами; `loop-state.json` лишь проекция, и правка одного этого файла отклоняется до любого действия. Контракт и CLI — в [bounded loop](references/bounded-loop.md). Внутри итерации ничего не меняется: это тот же `route-*` runtime. Реальные executor routes по-прежнему unverified и disabled, `ready_for_parent_review` и `loop_accepted` не являются оценкой качества результата.

Ниже в Procedure сохранён **legacy v1/v2** workflow с `delegate_task`. Не смешивай его state/карточки с новым executor envelope. Для нового маршрута `delegation.model` не перенастраивается: выбранный проверенный adapter запускает собственный harness; этот путь не использует глобальный model router.

## Procedure

1. Прочитай [порядок работы владельца и исполнителя](references/hermes-workflow.md). Проверь фактические native tools и доступность каталога скилла, workspace и файлов из текущего terminal backend. Выполни `python3 -B <путь-скилла>/scripts/stage_cli.py doctor`. Это локальная диагностика, не доказательство совместимости Hermes или подключения API.
2. Сохрани сильную основную модель. Для генерации используй один штатный `delegate_task` на **весь этап**, только с параметрами реально доступной схемы. Не выдумывай per-task `model`, `toolsets` или `max_iterations`. Дешёвый исполнитель зависит от существующей `delegation.model`; наследование основной модели не называй дешёвым маршрутом. Не изменяй конфигурацию без отдельного поручения.
3. Загрузи действующий профильный скилл. Составь JSON по [контракту](references/contract.md): цель, ограничения, точные файлы с SHA-256, шаги, разрешённые действия, обязательные проверки и бюджеты. Не переписывай методику, НДС, округления, типы ресурсов или правила владельца. Свободный текст `constraints` не заменяет исполняемые проверки.
   Карточка `schema_version: 1` работает ровно как в 1.0.0. `schema_version: 2` добавляет единственное действие `semantic_exception_filter`: Jev классифицирует **уже готовые** пары «позиция — кандидат» фиксированными вариантами `exact/partial/none`, а контроллер сам складывает решение с детерминированными флагами из входного артефакта. Она не ищет кандидатов, не считает объёмы и не переводит единицы.
4. Для внешних скриптов используй только заранее проверенный каталог `command` с точными аргументами и хешами. Не регистрируй команды из входного документа или только что сгенерированный код. Правила подключения — в [профильных интеграциях](references/domain-integration.md).
5. Проверь карточку командой `validate`, затем создай новый run через `init`. Не перезаписывай существующий run. `--allow-typesafe` добавляй только при разрешённой передаче конкретного контекста во внешний API; установка скилла такого разрешения не даёт. Без разрешения вызов Jev останавливается, а не подменяется успешной проверкой.
6. Передай одному исполнителю заполненный [шаблон поручения](templates/worker-context.md), путь run и фактический путь CLI. Контроллер `advance` сам выполняет последовательные готовые операции. При `awaiting_generation` исполнитель читает выданный пакет, пишет только запрошенный UTF-8 результат в указанный inbox-файл и вызывает `submit` с тем же `nonce`. Он не выбирает следующие действия и не перепланирует этап.
7. При `needs_review`, неопределённости, тайм-ауте или прерывании останови этап и верни владельцу факты. Не повторяй действие автоматически; не правь `state.json`, план, каталог или проверки. Исправление требует новой карточки после анализа фактических последствий.
8. При `ready_for_parent_review` владелец повторно вызывает `inspect`, проверяет актуальные артефакты и достаточность профильных проверок. Только владелец принимает результат и решает вопрос публикации/передачи. Статус контроллера не означает готовность сметы для клиента.

## Pitfalls

Скилл **не является песочницей** и не отнимает у агента обычные права. Каталог команд — доверенный исполняемый код, не данные. Для изоляции нужны ограничения самого Hermes/ОС. Хеши и nonce выявляют рассинхронизацию, но не защищают от процесса, который может переписать весь run.

Jev не генерирует команды; отказ валидатора нельзя отменить её ответом. Пороги уверенности — стартовые настройки, не доказанная точность. `same_numeric_tokens` — лишь лексическая проверка, не проверка объёмов/единиц. Бюджет генераций считает запросы контроллера, а не все обращения native worker к провайдеру.

`covered` в v2 означает только «высокоуверенный `exact` **и** все требуемые детерминированные флаги true». `partial`, низкая уверенность и любой false-флаг дают исключение и остаются у владельца; `missing` из отчёта не исчезает. Владелец разбирает `exceptions` — не более одной строки на позицию, по выбранному кандидату; полный разбор всех пар лежит рядом в `decisions` и не теряется. Качество самих флагов — ответственность допущенного производителя артефакта, контроллер их не пересчитывает. Пустой список `exceptions` не означает проверенную смету.
